# Member Profile identity and preference layout — WAP-296

[WAP-296](https://linear.app/mikebeezy/issue/WAP-296/member-profile-align-identity-and-compact-notificationlanguage) follows the explicitly requested platform UI/UX pass. Baseline source: `877f1862d03a526ca4b1c252bcaedbc9c960b954`. This is a local implementation candidate; hosted and production acceptance are separate release gates.

The real `MemberProfileKit` fixture at `/dev/member/profile?live=1` showed centered identity text beside left-aligned badges. The inline `textAlign: 'center'` overrode the intended responsive utility. On 1280/1440px desktops, the Notifications card also stretched to the Account details card's approximately 740px height, while Language started around y1218 despite substantial unused preference-column space. The earlier mobile grid-span/label/focus fixes remain present and are not reopened.

The candidate uses responsive text alignment and the discovered Astryx `VStack` to group Notifications and Language in the existing third desktop grid column. Cards retain their kit styling and natural heights. Account details precedes Notifications, Language, Password/security and Delete account in DOM order; mobile/tablet remain stacked. Fields, intake passthrough, save/error handlers, photo control, notification controls and security actions are unchanged.

Local Chromium evidence uses the actual Next fixture, portal shell, CSS and component with synthetic member data, both themes and widths 320/375/390/768/1280/1440. All writes and external/provider requests were blocked, and no upload, save, push-subscription, reset or deletion action was invoked. This does not certify an authenticated production journey. The 30-case AI Tools/Profile baseline had no horizontal overflow or page errors; AI Tools' already-shipped overview spacing was readable, so this patch does not redesign it.

Durable artifacts: `/workspace/artifacts/wap-platform-uiux-20261011/desktop-evidence.json`, `profile-after-measurements.json`, `profile-final-browser.json`, and viewport/identity screenshots under `screenshots/before` and `screenshots/after`. The paired browser check records the actual scroll position for readable preference screenshots and checks unchanged heading/field order and keyboard focus sequence. Existing contact-save regressions verify contact edits and intake-field passthrough, including cleared-address persistence. Local prepush and KB receipts are kept in the same artifact folder; they do not imply hosted or production approval.

Guidance: the UI/UX Pro Max cloud query contract was applied to the available repository search database. The UX navigation query returned keyboard/heading/skip-link guidance. A generic Next.js result was rejected and one narrowed React query supplied relevant labeling/focus guidance. Astryx CLI discovery returned the existing settings template and documented `VStack` props. Existing kit tokens and domain components take precedence over generic palette or template suggestions.
