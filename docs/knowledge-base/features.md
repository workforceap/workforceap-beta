## Application and staff workflow contracts

- Application browser recovery is an untrusted convenience. [Saved browser state](../../lib/apply/applyBrowserState.ts) validates shapes, current program slugs and expiry, and binds program choices and account drafts to the exact eligibility snapshot. Funding/contact/background panels remain inside the existing eligibility step. [Recovery paths](../../lib/apply) preserve only the server-resolved school referral and validated program; the signup API still owns eligibility, guardian, sponsorship and referral enforcement. Cold-entry pages show a recovery action rather than a completed-step hero. Legacy untimestamped completed records remain compatible and cannot prove their age.
- Public application-status link (product call 28a, #2489): an applicant who has no portal login yet can check their status from the email they applied with. [The lookup route](../../app/api/apply/status-lookup/route.ts) returns one body for every address; the match and the send run after the response, so neither wording nor timing reveals whether an address is on file, and the per-IP and per-email rate limits in [rate-limit](../../lib/rate-limit.ts) are counted for every address (do not quote the limits in copy). When an application exists, [statusLinkRequest](../../lib/apply/statusLinkRequest.ts) emails a [signed, stateless link](../../lib/apply/statusLinkToken.ts) bound to the application, its organization and a keyed hash of the address; the link expires 30 minutes after it was requested ([`APPLICATION_STATUS_LINK_TTL_MINUTES`](../../lib/apply/statusLinkConstants.ts), the only place the number lives) and there is no SMS channel. [The view page](../../app/apply/status/view/page.tsx) loads the row through [statusLookup](../../lib/apply/statusLookup.ts) under the applicant's own tenant scope, refuses to render when the token's email hash no longer matches the row, speaks the member words from [memberApplicationStatus](../../lib/member/memberApplicationStatus.ts), and shows the counselor's first name only, never a surname, because a link holder is not an authenticated member. The Astro catalogue's `apply.status*` copy mirrors the Next `apply.status*` copy with the expiry spelled out; [the parity spec](../../tests/lib/apply-status-copy-parity.spec.ts) pins both.
- After a Yes to "receiving TANF, WIC and/or SNAP", the apply flow, member eligibility form, public questionnaire and WIOA self-screening also capture which programs and whether the person wants help applying (WAP-53). [Shared normalization](../../lib/apply/publicAssistance.ts) clears both when the parent answer is not yes and requires at least one program only when a client sends the field, so older yes/no payloads and snapshots still parse. The answers are stored separately from the yes/no (`apply_eligibility_screenings.public_assistance_programs` / `public_assistance_help_requested`, and optional WIOA snapshot answer keys), appear in the eligibility datasheet, member export, review snapshot evidence, staff WIOA panels and screening emails, and surface a `help_applying_requested` applicant-triage reason. A help request is a staff signal, never verified enrollment; WIC named alone does not count as a WIOA low-income indicator (`wic_only_review`).
- Member message routing resolves the counselor of record at send time. Staff visibility of unanswered member messages (WAP-168): [countUnansweredMemberThreads](../../lib/messages/superAdminMessageQueries.ts) counts member threads whose latest member message has no staff reply regardless of age; it drives the `/admin/messages` opener, the stats route and the admin `Messages` nav badge (`member_messages_unanswered`), replacing the 48h-only badge. [The backfill](../../lib/messages/unansweredBackfill.ts) (`npm run db:backfill:unanswered-messages`, dry run by default) creates the missing staff notification for member messages sent before the admin fallback existed; it is idempotent and skips threads that already have a staff `message` notification since the member wrote.
- Member help and self-reported certificates on default pages (WAP-188 Phase A): the default [help page](../../app/(portal)/dashboard/help/page.tsx) carries a "Need a person?" card ([NeedAPersonCard](../../app/(portal)/dashboard/help/NeedAPersonCard.tsx)) with Request help and Share feedback, which used to render only on the legacy home. [resolveHelpRequestRecipient](../../lib/member/helpRequestRecipient.ts) is the one recipient rule for the page and `POST /api/member/request-help`: the route's existing rule (the counselor on the newest active assignment, else the team inbox). The stricter Messages definition (active, same-organization, not-deleted counselor) is not applied; switching is an email-routing change awaiting product-owner sign-off. The route reports `sentTo` and `sentToName`, and the confirmation names a counselor only when that name matches the one the page showed. The page names the counselor or says there is none, and points the Messages quick link and benefit copy at the team when there is no counselor; [copy](../../lib/member/helpContactCopy.ts) promises no reply time and says WorkforceAP staff (the admin-only `/admin/feedback`) read feedback. The default [My Certificates](../../app/(portal)/dashboard/certifications/page.tsx) view passes the self-report [CertificationAddForm](../../components/portal/CertificationAddForm.tsx) into `MemberCertificatesKit` (`addCertificateForm`); saves are `pending` for staff review (WAP-20) and the confirmation follows the status the route returns. Specs: [help](../../tests/app/dashboard-help-need-a-person.spec.tsx), [route](../../tests/api/member-request-help.spec.ts), [form](../../tests/components/certification-add-form.spec.tsx).
- [Application review](../../lib/admin/applicationReview.ts) and [WIOA evidence](../../lib/wioa) keep decisions, evidence and audit changes in real transactions. Staff clients submit the screening submission and review revisions they loaded; missing or changed revisions return a conflict and require reload. Counselor decisions recheck the current assignment under the member lock. Bulk reviews report committed and failed items separately. Denial reasons remain optional; no funding or qualification threshold is changed by this contract.
- [Persisted risk](../../lib/member/persistedAtRisk.ts) scopes and deduplicates members before paging, preserving actual event activity and nulls. It is a projection of persisted risk records, not a new scoring policy. [Partner attention](../../lib/partner) similarly filters eligible referrals before paging, carries a scoped cursor, and reports full tier counts. Cursor timestamps bound new referrals; changes to existing referrals can still move rows and warrant refresh. Saving a note must preserve its confirmed result across older reads and clear only the submitted draft revision.
- [Event names](../../lib/events/names.ts) separate the server vocabulary from the smaller browser allowlist and carry `LEGACY_EVENT_NAME_ALIASES` for spellings persisted before the taxonomy was enforced; readers use `eventNameReadCandidates`. [Event persistence](../../lib/events/track.ts) is the only module that calls `memberEvent.create` (ESLint `no-restricted-syntax` + [memberEventWriters](../../lib/events/memberEventWriters.test.ts)); it offers a throwing transaction-aware writer for atomic domain operations and a best-effort wrapper for observational callers, and stores any alias under its canonical name. A browser cannot claim a server-only completion or approval event.
- Internal API documentation lives in [private source data](../../data/api-docs), rendered through the super-admin page and protected spec route with private, non-cacheable responses. The generator must never write the catalog or specification back into `public/`.
- Public program catalog presentation no longer publishes or ranks by the historical salary field. Actual recorded placement outcomes remain separate. Cookie consent is a localized, nonmodal region in both rendering stacks; the React banner requires the existing root locale provider. Shared status adapters preserve the different legacy and kit meanings of danger.

- Counselor guided tour (tours wave 2): `counselor.home` in the [tour registry](../../lib/tours/registry.ts) is written for Today — three page anchors in [CounselorTodayKit](../../components/portal/kit/pages/counselor/CounselorTodayKit.tsx), three `tourTarget` rail rows (`My members`, `At-risk members`, `Messages`) and the header Help trigger. The counselor layout calls [getTourOffer](../../lib/tours/getTourOffer.ts) (`guided_tours_v2` for the user + their `UserTourState`; [shouldOfferTour](../../lib/tours/offer.ts) never re-offers a COMPLETED/DISMISSED row at the current version) and hands the result to `CounselorPortalShell`: `enabled` shows [PortalHelpMenu](../../components/portal/PortalHelpMenu.tsx) ("Take the tour" reopens it after any dismissal, plus the portal guide), `offer` shows the one-time [TourOfferStrip](../../components/onboarding/TourOfferStrip.tsx) ("Not now" writes DISMISSED at step 0). Nothing renders until the flag row exists. `POST /api/onboarding/reset` also deletes the portal's tour rows (`counselor` accepted) so QA can re-see the strip. Specs: [tests/tours](../../tests/tours).
- [Attention model](../../lib/attention) is the single "who needs attention" rule set for the admin Command Center (`/admin`), the Detailed overview (`/admin/overview`) and the counselor Today, Overview, Inbox zero, Triage and Work queue. `/counselor` lands on [Today](../../app/(portal)/counselor/today/page.tsx) — one list grouped by the kind of contact each member needs (`toTodayQueue`: at risk, reply owed, quiet, follow-ups, new to you, celebrate), each member once at their primary reason, on-track members never listed; the Caseload overview moved to `/counselor/overview`. Vocabulary and thresholds live in [reasons.ts](../../lib/attention/reasons.ts) (risk alert, no activity 30 d / 10 d, reply overdue 48 h / 24 h, no counselor contact 7 d, resume missing 3 d, application stalled 5 d, pending application, missing info, new without counselor, stale training, computer-support follow-up; milestones celebrate and never count). One fact loader ([loadFacts.ts](../../lib/attention/loadFacts.ts)) feeds [counselor.ts](../../lib/attention/counselor.ts) (assigned members) and [admin.ts](../../lib/attention/admin.ts) (member-role roster only; staff never count). Pages render pure projections from [counselorViews.ts](../../lib/attention/counselorViews.ts) and [adminViews.ts](../../lib/attention/adminViews.ts); [adminAgreement.test.ts](../../lib/attention/adminAgreement.test.ts) and [counselorAgreement.test.ts](../../lib/attention/counselorAgreement.test.ts) pin that every surface prints the same members and counts, each labelled with its rule.
- Admin Today (`/admin`, WAP-190) leads with an org-wide "Waiting on your decision" list ([adminApprovalQueue.ts](../../lib/admin/adminApprovalQueue.ts), [loadAdminApprovalQueue.ts](../../lib/admin/loadAdminApprovalQueue.ts)): every PENDING application and waiting WIOA intake in the actor's org — not the enrolled-only admin caseload — on the counselor builder and SLA, each row linking to the Applications workbench card or the member's Eligibility tab. The admin rail's first section, Daily work, is always open and holds the queue-clearing rows (Today, Applications with a pending badge, Funding eligibility, Certificates, Program requests, Students, Messages); every other section starts closed ([portalNav.ts](../../lib/nav/portalNav.ts)).

## Shared files with a wide change impact

The generated [reference summary](generated/summary.json) identifies heavily imported files. Prisma, authentication, role resolution, request GUC helpers, the program catalog and tenant resolution sit on many paths. Review reverse references before changing their return values, failure behavior or defaults.

The count is static import references across indexed source, including tests and tooling. It is not runtime request volume, cyclomatic complexity, or a security score.
